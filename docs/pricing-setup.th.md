## รูปแบบใช้งานล่าสุด

ผู้ใช้ให้เอาการเปิดไฟล์/ดาวน์โหลดออก เหลือบันทึกแผนในระบบและเปิดผ่านแท็บแผนที่บันทึก ข้อความเกี่ยวกับไฟล์ในประวัติด้านล่างเป็นพฤติกรรมรุ่นเก่า

# สถานะล่าสุด: เปิดให้ dev และ boss

ผู้ใช้อนุมัติเปิด username boss แล้ว ทั้ง dev/boss อ่าน คำนวณ บันทึก และเปิดแผนร่วมกันได้ ค่าเริ่มต้น PRICING_ALLOWED_USERS=dev,boss บัญชีอื่นแม้ role dev/boss ก็เข้าไม่ได้ ระบุ env เป็น dev หรือ boss เพื่อจำกัดภายหลังได้ โดยไม่เปลี่ยนสิทธิ์โมดูลอื่น ส่วนด้านล่างเก็บประวัติรอบ dev-only ก่อนอนุมัติ

# รอบตรวจงานปัจจุบัน: เฉพาะ username dev

Production ใช้รหัสชีตส่วนตัวที่ผู้ใช้อนุมัติเป็นค่าเริ่มต้นใน pricingStore.js เมื่อ VERCEL_ENV=production จึงไม่ต้องตั้ง env เพิ่มผ่าน Vercel หากระบุ PRICING_SHEET_ID จะใช้ค่าที่ระบุแทน Local/preview ไม่มีค่าเริ่มต้นและยังต้องตั้ง env เอง รหัสไฟล์ไม่ใช่ credential ทุกคำขอยังต้องผ่าน auth และอนุญาตเฉพาะ username dev เหมือนเดิม

ผู้ใช้สั่งให้ dev ตรวจคนเดียวก่อนให้บอสเห็น การทดสอบเดิมที่ boss เคยอ่านได้เป็นประวัติก่อนเปลี่ยนข้อกำหนด ปัจจุบัน boss ถูกปฏิเสธทุก Pricing API แม้ถือ role dev หรือใช้ env เก่า `dev,boss` เมนูอาศัยผลตรวจสิทธิ์จาก server

# เปิดใช้หน้าตั้งราคาและกำไร

หน้าอยู่ใน PAYI Ops เมนู “ยอดขายและการตลาด → ตั้งราคาและกำไร” หรือเปิด `/?tab=Pricing`

## สิ่งที่ทำได้

- คำนวณสินค้าเดี่ยวหรือเซ็ตที่ระบุส่วนประกอบและจำนวนเอง
- กรอกต้นทุน แพ็ค กล่อง ค่าส่ง ค่าธรรมเนียม ส่วนลด Ads และ Affiliate
- หาราคาจากกำไรเป้าหมายเป็นบาทหรือ margin
- ดูกราฟราคาขายและยอดขายจำลอง เปรียบเทียบแผนที่มีหน่วยเดียวกัน
- บันทึกและเปิดแผนผ่านระบบเท่านั้น ไม่มีปุ่มอัปโหลดหรือดาวน์โหลดไฟล์
- เมื่อเชื่อมฐานส่วนตัวแล้ว บันทึกแผนและประวัติ revision ข้ามเครื่องได้

ไม่เก็บเงินรับจริงและไม่มี settlement import ใช้ [เว็บเครื่องคำนวณที่ผู้ใช้ระบุ](https://tainiyom.github.io/shopee-calculator-/) เป็นพื้นฐาน มี 24 หมวดสินค้า 10 วิธีชำระเงิน และร้านทั่วไป/Mall ตามตารางในเว็บ (อัตราระบุมีผล 4 ส.ค. 2569) การเลือกหมวด/ร้าน/วิธีชำระเงินจะโหลดอัตราพื้นฐาน จากนั้นแก้ตัวเลขเองได้ทุกช่อง เปลี่ยนหมวดหรือวิธีจ่ายอีกครั้งจะโหลดค่าพื้นฐานของตัวเลือกใหม่

สวิตช์ปิดคือไม่คิดรายการนั้น สวิตช์เปิดจึงนำเปอร์เซ็นต์ที่กรอกมาคิด งบการตลาดทุกตัวคิดจากราคาขายตามเว็บพื้นฐาน ได้แก่ แคมเปญ 5%, Seller Voucher 5%, Flash Sale 5%, Dynamic 3.21%, Exclusive 5%, Affiliate 10%, Ads 5% ตัวเลขเหล่านี้แก้ได้ทั้งหมด PRIME ลดคอมมิชชันตามหมวด, Xtra เพิ่ม Service Fee ตามหมวด, ส่วนลดร้านยอดต่ำเริ่ม 1 จุดเปอร์เซ็นต์ เปิด/ปิดเอง

สูตรพื้นฐานไม่หักส่วนลดการตลาดออกจากฐาน Commission/Transaction ซ้ำ Exclusive เป็นงบเปอร์เซ็นต์ ไม่ใช่ราคาขายใหม่ ค่าส่งลูกค้าจ่ายใช้กับฐาน Transaction และถือเป็นเงินส่งผ่านให้ขนส่ง ไม่บวกเข้ากำไร ตัวอย่างราคา 500 ต้นทุน 200 แพ็ค 15 ค่าส่ง 38 เปิด Exclusive 5% และ Affiliate 10% ได้ค่าธรรมเนียม 103.94 งบการตลาด 75 กำไร 106.06 บาท

มีปุ่มคืนค่าพื้นฐานตามเว็บ อัตราไม่อัปเดตตามประกาศอัตโนมัติ แผนที่บันทึกจะเก็บตัวเลขที่ใช้ในครั้งนั้นไว้ แผน/ไฟล์จากเครื่องคำนวณรุ่นก่อนยังใช้ความหมายสูตรเดิมจนกดเปลี่ยนเป็นสูตรตามเว็บ เพื่อไม่ตีความราคาหน่วยบาทเก่าเป็นเปอร์เซ็นต์เงียบ ๆ

## การตั้งค่าที่จำเป็นสำหรับข้อมูลจริง

1. ใช้ระบบล็อกอินเดิม เปิด `AUTH_SECRET` และใช้ username `dev` เท่านั้นในรอบตรวจงานนี้
2. เตรียม Google Spreadsheet ส่วนตัว แยกจาก `SHEET_ID` หลัก ตั้งการเข้าถึงเป็น Restricted แล้วแชร์ให้ service account เดิมเป็น Editor
3. ตั้ง `PRICING_SHEET_ID` บน server ให้ชี้ไปไฟล์นี้ ห้ามใช้ตัวแปร VITE สำหรับค่า config ลับ
4. ตั้ง `PRICING_ALLOWED_USERS=dev` เป็นชื่อบัญชีจริง ไม่ใช่ชื่อ role
5. restart dev server หรือ deploy ตามวิธีเดิม แล้วเข้าหน้าตั้งราคา จะสร้างแท็บประวัติเมื่อบันทึกครั้งแรก

หากยังไม่ตั้ง private sheet บัญชีที่มีสิทธิ์ยังอ่านสินค้า ราคาอ้างอิง สูตรเซ็ต และยอดขายจาก Ops ได้ คำนวณและเก็บแผนเป็นไฟล์ได้ แต่ปุ่มบันทึกเข้าระบบยังไม่เปิด หากปิด auth จะใช้ได้เฉพาะข้อมูลตัวอย่าง และการเก็บแผนในหน้าตัวอย่างเป็นหน่วยความจำที่หายเมื่อ refresh

ตัวเลือกสินค้า/สูตรเซ็ตอ่านจาก Ops หลังตรวจสิทธิ์แล้ว การเลือก SKU ใหม่จะใช้ต้นทุนที่เคยบันทึกของ SKU นั้นในธุรกิจเดียวกัน ถ้าไม่มีจะเว้นว่างให้กรอก ไม่ใช้ต้นทุนของสินค้าก่อนหน้า สูตรเดิมที่นำเข้ายังต้องตรวจส่วนประกอบและใส่ต้นทุนทุกตัว

## การเชื่อมข้อมูลสินค้าและยอดขาย

- ค้นด้วยชื่อ SKU สี ไซซ์ และชื่อตัวเลือกจากออเดอร์ โดยแยกธุรกิจ Payi / Payi Outlet / กรอบรูป
- ชื่อและตัวเลือกใช้ `product_aliases` ประกอบ metadata ใน `productMaster.json` และรายการคลัง สีหรือไซซ์ที่ไม่มีข้อมูลจะแสดงว่ายังไม่ระบุ ไม่เดาจากชื่อเอง
- ราคาเริ่มต้นใช้ `inventory_items.retail_price` พร้อมป้ายราคาอ้างอิงจากคลัง หากไม่มีราคาให้กรอกเอง ไม่ใช้ราคาสินค้าก่อนหน้าต่อ
- ต้นทุนเติมจากแผนสินค้าเดี่ยวล่าสุดของ SKU ในธุรกิจเดียวกัน ถ้าไม่มีให้กรอกเอง ไม่ใช้ราคาขายแทนต้นทุน
- สูตรเซ็ตอ่าน `set_recipes` โดยใช้ SKU + variation เดิมก่อน redirect ข้ามแถวแก้รหัสที่ `keep_set_sales=0` และไม่เขียนสูตรกลับคลัง
- เลือกสินค้าแล้วใช้ยอด 30 วันเป็นจำนวนขายจำลองเริ่มต้น กดใช้ฐาน 90 วันเพื่อใช้จำนวนขายหาร 3 เป็นฐาน 30 วัน หรือแก้จำนวนจำลองเองได้
- ยอดย้อนหลังนับถึงวันที่ที่เลือกตามปฏิทินไทย ขอบเขตเป็นธุรกิจ + Shopee ยังไม่แยกร้าน ตัดยกเลิก/คืนสินค้า กัน order_key ซ้ำ และนับเซ็ตเป็นเซ็ตที่ขายตรง ไม่แตกส่วนประกอบแล้วบวกซ้ำ
- แสดงช่วงวัน วันที่ล่าสุดที่พบ และเดือนที่ไม่มีแท็บ เพื่อให้เห็นข้อจำกัดของข้อมูล ราคาขายเฉลี่ยจากออเดอร์แยกจากราคาอ้างอิงในคลัง
- การบันทึกแผนเก็บช่วงวันและฐานจำนวนขายที่เลือกไว้ เปิดแผนเก่าแล้วไม่แทนยอดจำลองด้วยข้อมูลใหม่อัตโนมัติ
- โหมดตัวอย่างมี SKU `DEMO-TEE`, `DEMO-SOCK`, `DEMO-SET` สำหรับลอง flow ทั้งหมด โดยระบุชัดว่าเป็นข้อมูลตัวอย่าง ไม่ผสมกับคำตอบจาก API ข้อมูลจริง

ทดสอบอ่านจริง 14 ต.ค. 2569: ได้ทะเบียน 261 รายการ มีราคาอ้างอิง 44 รายการ สูตรเซ็ต 38 แถว และอ่านยอดขายย้อนหลังได้ พบข้อมูลออเดอร์ล่าสุด 10 ต.ค. 2569 การตรวจนี้อ่านอย่างเดียว ไม่มีการเขียนข้อมูลเดิมหรือเก็บเงินรับจริง

## ส่งมอบให้บอสภายหลัง

รอบปัจจุบันล็อกเพดานสิทธิ์ในโค้ดไว้ที่ username `dev` เท่านั้น แม้ server ยังมี env เก่า `dev,boss` บอสก็เข้าไม่ได้ ต้องได้รับคำสั่งเปิดให้บอสก่อนแก้เพดานใน `pricingAccounts()` และตั้งค่า allowlist ใหม่

ประวัติแผนส่งมอบเดิม (ยังไม่ใช้ในรอบนี้):

เมื่อผู้ใช้สั่งถอนสิทธิ์ ให้เปลี่ยน `PRICING_ALLOWED_USERS=boss` และ restart/deploy ไม่ลบบัญชี dev จาก Ops และไม่เปลี่ยนสิทธิ์โมดูลอื่น ทุก API ของ Pricing ตรวจรายการนี้ใหม่ในแต่ละคำขอ จึงไม่อาศัย role เก่าใน token เพื่อเปิดข้อมูล

เมนูตรวจสิทธิ์เมื่อกลับมา focus และทุก 60 วินาที หากถูกถอนสิทธิ์ component จะถูกถอดและข้อมูลในหน่วยความจำถูกทิ้ง การปิดสิทธิ์ในหน้านี้ไม่ลบสำเนาที่เคยดาวน์โหลด และหากต้องปิดการเข้าถึงข้อมูลโดยตรงด้วยต้องทบทวนสิทธิ์ spreadsheet/service account/deploy ในการส่งมอบ

## ทดสอบแล้ว

ใช้ `node --test test/pricing.test.js test/pricing-data.test.js test/pricing-api.test.js test/roles.test.js` ตรวจสูตร เงินสตางค์ เซ็ต ค่าธรรมเนียมต่อออเดอร์ เพดาน ส่วนลด ราคาเป้าหมาย ยอดขายเดือน ขอบเขตธุรกิจ/ตัวเลือก/วันที่ การกันนับยอดซ้ำ และสิทธิ์/การบันทึกผ่าน API แบบจำลอง โดยไม่เขียนฐานจริง

การบันทึกใช้ append revision ไม่แก้ทับประวัติ เมื่อ timeout ให้กดตรวจสอบผลบันทึกในหน้าเดิมก่อน retry ระบบใช้ request ID ตรวจรายการซ้ำ แต่ Sheets ไม่รับประกัน unique constraint หรือการแก้พร้อมกันแบบ transaction จึงควรหลีกเลี่ยงแก้สินค้าเดียวกันพร้อมกันสองบัญชี

## เตรียมขึ้นระบบ — ตรวจจริง 14 ต.ค. 2569

สร้าง `PAYI Pricing Private` แยกแล้ว: https://docs.google.com/spreadsheets/d/18vxUJ1bpJdj3DuxbCkOsnvzhDW1z5Vt0lAGhRP0krXY/edit

ตรวจสิทธิ์ตรงแล้ว มีเพียงเจ้าของและ service account เดิมเป็น Writer ไม่มี anyone/domain sharing ผู้ใช้อนุญาตการแชร์ Writer โดยตรงในแชต ตรวจบัญชี dev/boss ใน users จริงพบทั้งสองบัญชี

ผ่าน smoke test ด้วย token ที่เซ็นจาก secret สำหรับเครื่องทดสอบ: ผ่าน handler ตัวเดียวกับ server ตรวจ anonymous 401, บัญชีอื่นแม้ role dev ได้ 403, dev บันทึกจริง, boss recover อ่านกลับได้ และ retry request เดิมได้ revision เดิม ใช้ข้อมูลตัวอย่างที่ติดชื่อ `[ตรวจระบบ]` SKU `RELEASE-CHECK` เก็บไว้หนึ่งแผนเพื่อเป็นหลักฐาน ไม่ได้ทดสอบรหัสผ่านผู้ใช้หรือ login ผ่าน browser แทนผู้ใช้

ไฟล์ `.env.pricing.local` (gitignored) มี secret เฉพาะเครื่องทดสอบ พร้อม private sheet ID และ allowlist ใช้ร่วมกับ `.env` ห้ามนำ AUTH_SECRET ในไฟล์นี้ไปแทน secret เว็บจริง เพราะจะทำให้ session เดิมหมดอายุ

คำสั่งตรวจสภาพแวดล้อมเป้าหมาย (อ่านอย่างเดียว):

```powershell
node --use-system-ca --env-file=.env --env-file=.env.pricing.local scripts/pricing-preflight.mjs --online
node --use-system-ca --env-file=.env --env-file=.env.pricing.local scripts/pricing-smoke.mjs
```

คำสั่ง smoke เพิ่ม `--write-sample` จะบันทึกข้อมูลตัวอย่างที่ระบุชื่อชัดเจนหนึ่งแผน โดยจำ request ID ไว้ที่ tmp เพื่อไม่สร้างซ้ำ หาก timeout อย่าลบไฟล์ request แล้วเริ่มใหม่ ให้ recover ด้วย ID เดิมก่อน

คำสั่งเปิด local ที่ล็อกอินจริง:

```powershell
node --use-system-ca --env-file=.env --env-file=.env.pricing.local node_modules/vite/bin/vite.js --port 5191 --strictPort
```

### ชุดสำหรับ deploy

บน Vercel โปรเจกต์เดิม `payiops` ให้คง AUTH_SECRET และ Google credentials เดิม แล้วเพิ่มเฉพาะ:

```text
PRICING_SHEET_ID=18vxUJ1bpJdj3DuxbCkOsnvzhDW1z5Vt0lAGhRP0krXY
PRICING_ALLOWED_USERS=dev
```

ก่อนปล่อย production ให้ deploy preview จากชุดไฟล์นี้ ทดสอบ login ด้วยบัญชี dev และบันทึก/เปิดแผนหนึ่งครั้ง ทดสอบ boss และบัญชีอื่นเข้า URL/API ไม่ได้ จากนั้นจึง promote production ยังไม่ได้ตั้งค่าบน Vercel หรือ deploy ในขั้นเตรียมนี้ เพราะเครื่องไม่มี Vercel CLI session ที่ยืนยันแล้ว การตรวจในเครื่องไม่ใช่ผลตรวจ deployment จริง

ย้อนกลับ: ใช้ deployment ก่อนหน้าของ Vercel แผนใน private sheet คงอยู่ ไม่มี migration แตะข้อมูลออเดอร์/คลัง ไม่ถอนสิทธิ์ dev จนกว่าผู้ใช้สั่ง


## ตรวจบั๊กและตัวเลข 14 ต.ค. 2569

แก้ solver ให้หาราคาได้เมื่อยังไม่กรอกราคาขาย (ยังบังคับต้นทุนครบ), แก้ปัดเลขครึ่งสตางค์ เช่น 10.075 เป็น 10.08, คืนค่าธรรมเนียมไม่เปลี่ยนแผนฐานที่ล็อกไว้ และไม่วาดกราฟเทียบกับคนละ SKU/ธุรกิจ/ตัวเลือก เพิ่มข้อความสั้นใต้ส่วนจำลองอธิบายฐานที่ใช้ รุ่นคำนวณใหม่ engine 3 ส่วนแผนเดิมยังเก็บผล revision เดิมไว้

เทียบ source เว็บต้นฉบับ: อัตราครบ 24 หมวด / 10 วิธีชำระเงินตรงกัน ตรวจแยกด้วย integer arithmetic 3,840 กรณีผ่าน (24 × 2 ประเภทร้าน × 10 วิธีจ่าย × 8 ชุด PRIME/Xtra/ร้านยอดต่ำ พร้อมสลับ Ads/Exclusive) ในกรณีที่ตรวจผลต่างจากเว็บต้นฉบับสูงสุด 1 สตางค์ เพราะต้นฉบับรวมค่าทศนิยมก่อนปัด ส่วนระบบนี้ปัดรายรายการก่อนรวมให้ยอดตรงกับรายการในใบสรุป ตัวอย่างราคา 549.99 หมวดอิเล็กทรอนิกส์ต่ำสุด ร้านทั่วไป จ่ายปกติ ต้นทุน 200.25 แพ็ค 15.50 กำไรระบบ273.11 เทียบต้นฉบับ273.10 บาท

ผลตรวจนี้ยืนยันตามสูตรและค่าพื้นฐานของเว็บต้นฉบับ ไม่ใช่การตรวจประกาศ Shopee ล่าสุดหรือยืนยันเงินรับจริง


## แก้ไข ลบ และกู้คืนแผน

ในแท็บแผนที่บันทึก กดแก้ไขเพื่อปรับแผนเดิมแล้วบันทึกเป็น revision ใหม่ กดลบแล้วกดยืนยันในรายการเพื่อย้ายแผนเข้าถังขยะ กู้คืนได้จากปุ่มถังขยะ ทั้ง dev/boss ใช้ได้ ไม่ลบแถวหรือประวัติถาวร การลบและคืนแผน append revision พร้อม operation/deleted และ parent revision ตรวจความขัดแย้ง/คำขอซ้ำ/timeout เหมือนการบันทึก แผนที่ถูกลบไม่ใช้เติมต้นทุนและไม่รับการแก้จากหน้าเก่าจนกู้คืน
