อัปเดต 11 กันยายน 2026 (Asia/Bangkok)

โปรเจกต์หลักอยู่ที่ `C:\Users\PC\Desktop\MONA\New\mona-ops` ระบบ Next.js + Express/TypeScript + PostgreSQL อยู่ใน `backend/core` พร้อมหน้าจัดซื้อ CFO ค่าแอด ผู้ใช้ ตั้งค่า LINE และแคตตาล็อก SSR แอป Vite/Sheets เดิมยังแยกทำงานตามเดิม ข้อมูลเก่าไม่ได้ถูกย้ายเข้าฐานบัญชีโดยอัตโนมัติ

## เปิดใช้งาน

ติดตั้ง PostgreSQL 18.4 แบบ portable, Ollama และโมเดล Qwen3.5:0.8b ในเครื่องนี้แล้ว มีฐานถาวร `mona_ops` และบริษัท MONA ที่ยังไม่มีรายการขายจริง

```powershell
cd C:\Users\PC\Desktop\MONA\New\mona-ops
npm run ops:start
```

เปิด http://localhost:3000 และใช้บัญชีใน `backend/core/.local/owner-login.txt` เก็บไฟล์นี้เป็นความลับ อย่าแนบแชตหรือ commit ลง Git เปิด PowerShell นี้ค้างไว้ขณะใช้งาน กด Ctrl+C เพื่อปิดเว็บ/API จากนั้น `npm run local:stop --prefix backend/core` เมื่อต้องการหยุด PostgreSQL ด้วย

หากติดตั้งใหม่ ใช้ Node.js 24 และรันตามลำดับ:

```powershell
npm ci
npm run ops:install
npm run ops:build
npm run ops:start
```

ตัวติดตั้งดาวน์โหลดซอฟต์แวร์และโมเดลหลาย GB ไม่ต้องผูกบัตรเครดิต และไม่สร้างบริการคลาวด์ให้เอง พอร์ตที่ใช้: เว็บ 3000, API 3001, PostgreSQL 55432, Ollama 11434 ทุกบริการผูกกับ loopback ของเครื่องร้าน

## เริ่มงานจริง

1. เข้าด้วย owner แล้วสร้างบัญชีพนักงานในแท็บผู้ใช้ บทบาท STAFF ส่งคำขอ; BOSS อนุมัติจัดซื้อ; FINANCE จัดซื้อและการเงิน; OWNER ตั้งค่าระบบได้ด้วย
2. บันทึกผู้รับเงิน ส่งคำขอพร้อมข้อความ/ลิงก์/รูป เลือก COD หรือสำรองจ่าย ระบบเสนอหนึ่งในสี่สถานที่และให้ผู้อนุมัติตรวจทุกครั้ง
3. เมื่อรับของ ให้กรอกยอดจริงและแนบบิล ระบบรับรู้ค่าใช้จ่ายและเจ้าหนี้ครั้งเดียว รายการหยิบจากบ้านใหญ่ไม่มีการสร้างยอดโอน
4. รวมรอบจ่าย ตรวจแต่ละผู้รับ แล้วอนุมัติ โอนผ่านธนาคารด้วยตัวเอง แนบหลักฐานก่อนยืนยันจ่าย ระบบบันทึกชำระเจ้าหนี้และเงินสด โดยไม่บันทึกค่าใช้จ่ายซ้ำ
5. CFO: สร้างสินค้าและต้นทุนที่มีวันเริ่มใช้ บันทึกยอดขายเมื่อส่งมอบสินค้า กรอกค่าแอด/ค่าใช้จ่ายคงที่ แล้วเปิดกำไรต่อออเดอร์ การรับรู้ยอดขายลงลูกหนี้ ไม่เท่ากับเงินเข้าธนาคาร

AI ประมวลผลในเครื่องด้วย Ollama หากโมเดลไม่พร้อมจะใช้กฎข้อความและให้คนตรวจ ไม่ส่งภาพหรือข้อความไปบริการ AI แบบเสียเงิน บิลเก็บใน PostgreSQL แยกบริษัท ภาพไม่เกิน 5 MB ต่อไฟล์และรวมไม่เกิน 1 GB ต่อบริษัท ภาพถูกตรวจและแปลงใหม่เพื่อลบ metadata

## ตั้งค่า LINE Bot จัดซื้อตัวใหม่ที่มีอยู่แล้ว

ใช้ Channel ของบอทจัดซื้อตัวใหม่โดยเฉพาะ ไม่มีการส่งต่อจาก webhook ของบอทสต็อก/HR เดิม

1. ต้องมี HTTPS origin ที่มือถือและ LINE เข้าถึงได้ ส่งต่อมายัง Next.js พอร์ต 3000 ผ่าน reverse proxy ของผู้ดูแล เครือข่ายปัจจุบันยังไม่ได้ตั้ง public HTTPS URL ให้
2. เข้าแท็บ **ตั้งค่า LINE / AI** ด้วย owner กรอก Channel Access Token, Channel Secret, LINE User ID ของผู้อนุมัติ และ HTTPS origin โดยตรงในหน้าเว็บ
3. ผู้รับต้องเพิ่มเพื่อนบอทใหม่ เลือกเปิดสรุปตามเวลาหากพร้อม แล้วบันทึก ระบบตรวจ Token กับ LINE และแสดง Webhook Path
4. ตั้ง Webhook URL ของ Channel ใหม่เป็น HTTPS origin ตามด้วย Path ที่ระบบแสดง เปิด Use webhook และกด Verify ใน LINE Developers
5. เริ่ม `ops:start` ใหม่เพื่อโหลดค่าตามเวลาและ public origin ใหม่ หลังตั้ง HTTPS ให้เปิดหน้าเว็บจาก origin นี้ในการเข้าสู่ระบบ

Next.js รับ POST `/webhooks/line/:companyId/:routeId` และส่ง raw bytes/signature ให้ Express ตรวจ HMAC, bot destination, บริษัท, ผู้อนุมัติ และ token ของปุ่ม ก่อนเปลี่ยนบัญชี

สรุปทำงานทุกวันหลัง 17:00 น. Asia/Bangkok หากเปิดเครื่องหลังเวลา จะจัดสรุปของวันนั้นครั้งเดียว รวมรายการค้างด้วย ปุ่มซื้อแล้วพาไปกรอกยอด/บิลในเว็บ ปุ่มโอนแล้วทำงานเมื่ออนุมัติรอบและเตรียมหลักฐานครบ จึงไม่สร้าง PAID จากการกดปุ่มลอย ๆ

ระบบตรวจโควตาก่อนส่งและหยุดเมื่อถึงเพดานที่ต่ำกว่าระหว่างโควตาบัญชีกับ 300 ข้อความต่อเดือน ไม่อัปเกรดแพ็กเกจให้อัตโนมัติ การทดสอบใช้ bot/signature จำลอง ยังไม่ส่งข้อความจริงจากบอทใหม่ของร้าน

## ค่าใช้จ่ายและขอบเขต

ระบบฐานนี้ใช้ซอฟต์แวร์ฟรีและเครื่องที่ร้านมีอยู่ ไม่มีค่า AI API/ฐานข้อมูลคลาวด์/โฮสติ้งที่สมัครเพิ่ม ค่าไฟ อินเทอร์เน็ต อุปกรณ์ ค่าซื้อสินค้า และค่าธรรมเนียมธนาคารหรือ Payment Gateway เป็นค่าใช้จ่ายของผู้ให้บริการนั้น ระบบไม่ได้รับประกันว่าทุกต้นทุนธุรกิจเป็นศูนย์

Vercel Hobby ไม่ใช่ตัวเลือกสำหรับโฮสต์ธุรกิจนี้ เพราะกำหนดการใช้ส่วนบุคคลที่ไม่ใช่เชิงพาณิชย์ ดู [Vercel Hobby](https://vercel.com/docs/plans/hobby) และดู [ราคา LINE OA ประเทศไทย](https://lineforbusiness.com/th/service/line-oa-features) ก่อนเปลี่ยนแผน

กำไรเป็นกำไรก่อนภาษีเงินได้ ใช้ต้นทุนตามเวลาขายและปันส่วนค่าใช้จ่าย ยอดปันส่วนยังเปลี่ยนได้เมื่อเพิ่มออเดอร์/ค่าแอดในช่วงเดียวกัน ต้องกรอกค่าแอดครบและกระทบยอดบัญชีจริง การจัดซื้อปัจจุบันรับรู้ของใช้สิ้นเปลืองเต็มยอด ไม่ใช่ระบบสินทรัพย์ถาวร/รับคืนภาษีซื้อ และยังไม่ได้ลงยอดยกมาจาก Sheets

Gateway adapters มีชุดทดสอบ Stripe/Omise/2C2P แต่ยังไม่ได้เชื่อม merchant จริง การอนุมัติรอบจ่ายไม่ใช่ API โอนเงินจริงให้หลายบัญชีในคลิกเดียว

## สำรองและตรวจการกู้คืน

```powershell
npm run ops:backup
npm run ops:verify-backup
```

สำรองที่ `backend/core/.local/backups` รวม database.dump, SHA256 และ runtime configuration ที่มีรหัสลับ ควรคัดลอกไปดิสก์ส่วนตัวอีกตัว คำสั่ง verify ตรวจ checksum และกู้ลงฐานชั่วคราวแยก จากนั้นลบเฉพาะฐานทดสอบ ไม่เขียนทับข้อมูลร้าน การเก็บสำรองบนดิสก์เดียวไม่ป้องกันดิสก์เสีย
