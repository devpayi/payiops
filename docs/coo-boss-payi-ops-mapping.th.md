# จับคู่ COO app กับงานบอสใน PAYI Ops

ตรวจจากไฟล์ใน `C:\Users\PC\Desktop\COO app` และโค้ด PAYI Ops วันที่ 8 ตุลาคม 2569 การตรวจนี้เป็นการอ่านไฟล์ ไม่ได้เปิดข้อมูลจริงหรือยืนยันการใช้งาน production

## ข้อเท็จจริงที่ต้องใช้ตัดสินใจ

- COO app มีทั้งคลัง `PROMPT.md` และไฟล์ HTML ที่สร้างแล้ว เช่น COO Command Center, Daily Flash Report, Approval Center และ Alert Engine
- HTML เหล่านี้เป็นแอปแยก ใช้ข้อมูลตัวอย่าง, `localStorage` ในเบราว์เซอร์ และ CSV/JSON สำหรับย้ายข้อมูล ไม่พบการเชื่อม API หรือบัญชีผู้ใช้กับ PAYI Ops ในไฟล์ที่ตรวจ
- ตัวอย่างของ COO Command Center ตั้งบนธุรกิจความงามขนาด 300–1,500 ล้านบาท และมีตัวเลขสมมติ เช่นเงินสด 42.5 ล้านบาทและพนักงาน 186 คน ห้ามนำตัวเลขเหล่านี้มาแสดงเป็นข้อมูล PAYI
- บอสใน PAYI Ops เข้า Dashboard ยอดขาย, Inventory, Stock Movement, Import Tracking, HR, HR People, WHT Cert, Fulfillment และหน้าอื่นได้ตาม role แต่ `CFO Dashboard` แสดงหน้า “กำลังจัดทำ” สำหรับบอส แม้มีชื่อในเมนู
- Home ของ PAYI Ops ตอนนี้เป็นรายการเมนู ยังไม่มีสรุปงานบอสจากข้อมูลเดิม

## ต้นแบบที่ตรงกับงานบอส

หน้าแรกของบอสควรตอบในเวลาสั้นๆ ว่า **วันนี้มีอะไรต้องดู** โดยไม่ให้กรอกหรือยืนยันซ้ำ:

1. ยอดขายล่าสุดและวันที่ออเดอร์ล่าสุด จาก Dashboard เดิม
2. คำขอลารออนุมัติ จาก HR เดิม พร้อมทางไปคิวเดิม
3. สินค้าเสี่ยงขาด/เอกสารนำเข้าค้าง จาก Inventory และ Import Tracking เดิม เฉพาะเรื่องที่เข้าเกณฑ์จริง

แต่ละบรรทัดต้องมีแหล่งข้อมูล เวลาที่ข้อมูลล่าสุด เหตุผลที่ยกขึ้นมา และลิงก์ไปหน้าที่แก้ปัญหาอยู่แล้ว ถ้าข้อมูลเก่าหรือโหลดไม่ได้ ให้บอก “ยังสรุปไม่ได้” สำหรับเรื่องนั้น ไม่แสดงศูนย์หรือสถานะปกติแทน

## ลำดับที่ควรทำหากจะพัฒนา

1. ตรวจ response ของ API ที่ใช้จริงและสิทธิ์ role boss โดยไม่เปลี่ยน endpoint เขียนข้อมูล
2. ทำ Boss Home แบบอ่านอย่างเดียวใน PAYI Ops จากข้อมูล 3–4 แหล่งที่มีอยู่ โดยใช้ cache/คำขอเท่าที่จำเป็น
3. ทดลองกับบัญชีบอสจริงว่ากดไป HR, Inventory และ Import Tracking ได้ และไม่มีเมนูที่เข้าถึงไม่ได้
4. ค่อยพิจารณารายงานเงิน/อนุมัติข้ามระบบเมื่อมีเจ้าของข้อมูลและแหล่งข้อมูลจริง ไม่ย้าย localStorage/CSV ของ COO app มาเป็นฐานใหม่
